Rules worth knowing

These cover most of what students actually want to change:

  • Spacing — margin and padding. Margin is space outside an element, padding is space inside it. Most layout complaints are a spacing problem.
  • Type detail — letter-spacing, line-height, text-transform. Small adjustments, large effect on headings.
  • Hover — a:hover. What changes when the cursor is over a link.
  • Cursor — cursor. Choose a cursor that remains clear and usable.
  • Transition — transition. Makes a change happen over time rather than instantly. Keep it under 300ms or the site feels slow.

Work and debug systematically

  • One change at a time. Change one rule at a time, inspect the result, and keep or remove it.
  • Comment what you write. /* bigger gap under project titles */ explains the purpose of a rule when you return to it.
  • Inspect before guessing. Right-click the element, Inspect. The browser shows you exactly which rules are hitting it and which are being overridden.
  • Keep a copy. Paste your working CSS into a note before a big experiment.

Copy and paste: HTML and CSS

HTML describes the content and structure. CSS controls its appearance. In this example, HTML creates one paragraph and gives it a class; CSS uses that class to change its colour, size and spacing.

Where to paste: Open a practice page in Cargo and use Code View → HTML for the HTML below. Append it without deleting existing content, then click Update. Paste the CSS into Site Settings → CSS/HTML → CSS, after your existing rules. Do not include HTML or <style> tags in the CSS editor. These exercises do not need the site-wide HTML tab.

HTML — paste into the page’s Code View

<!-- HTML creates the content. The class gives CSS a target. -->
<p class="wk5-intro">Hello, I am a designer documenting my process.</p>

CSS — paste into the site CSS editor

/* The dot selects elements with class="wk5-intro". */
.wk5-intro {
  color: #243c8f;         /* Text colour */
  background: #eef2ff;    /* Colour behind the text */
  font-size: 24px;        /* Text size */
  line-height: 1.5;       /* Space between lines */
  padding: 20px;          /* Space inside the paragraph */
  border-radius: 12px;    /* Rounded corners */
}

Try it: Replace the sentence with your own introduction. Change only the colour, then only the padding. Explain what changes and what stays the same. In color: #243c8f;, color is the property and #243c8f is its value.

Apply to one page: Replace the selector .wk5-intro with [id="YOUR_PAGE_ID"] .wk5-intro. Replace YOUR_PAGE_ID with the actual Cargo Page ID from the editor’s address bar. This limits the rule to that page. Keep the class name unchanged in the HTML.

Copy and paste: dropdown navigation and overlays

Use your Week 4 sitemap to choose the main labels and the pages grouped beneath Work. This example uses a native HTML disclosure: click or tap Work to reveal its links, then click again to close. Keyboard users can focus Work and press Enter or Space. No JavaScript is needed.

A. Add a dropdown to your top navigation

Paste the HTML into the Code View of your navigation page. If you already have a menu, adapt or replace its navigation block rather than showing two menus. For persistent navigation, use Cargo’s Pin settings for that page. The menu below expands in the page layout and pushes content down; it does not float over other content. Use the Cargo overlay variation below when you want a panel above the page.

Replace every sample URL with the correct destination on your site. The paths shown here are examples, not pages created by this code. Use Cargo’s Link to Page control when assigning links in the visual editor, particularly for Cargo overlay destinations.

HTML — paste into your navigation page

<!-- Replace every sample href with a real page URL from your site. -->
<nav class="wk5-nav" aria-label="Main navigation">
  <a href="/">Home</a>
  <!-- details and summary create a click/tap dropdown without JavaScript. -->
  <details class="wk5-dropdown">
    <summary>Work</summary>
    <div class="wk5-submenu">
      <a href="/project-one">Project One</a>
      <a href="/project-two">Project Two</a>
    </div>
  </details>
  <a href="/journal">Journal</a>
  <a href="/about">About</a>
</nav>

CSS — paste once into the site CSS editor

/* A wrapping row for your top navigation. */
.wk5-nav {
  display: flex;
  flex-wrap: wrap;
  align-items: flex-start;
  gap: 12px 24px;
  font-size: 18px;
  line-height: 1.5;
}

/* Keep these rules limited to this menu. */
.wk5-nav a,
.wk5-nav summary {
  color: #202b35;
  padding: 10px 12px;
  border-radius: 6px;
}
.wk5-nav a {
  display: block;
  text-decoration: none;
}
.wk5-nav summary {
  cursor: pointer; /* The native triangle signals expandable content. */
}

/* The browser hides this content until details is open. */
.wk5-submenu {
  margin-top: 8px;
  padding: 8px;
  background: #f3f5f7;
  border: 1px solid #d9e0e6;
  border-radius: 8px;
}

/* Hover feedback plus a visible keyboard focus indicator. */
.wk5-nav a:hover,
.wk5-nav summary:hover {
  background: #e4e9f0;
}
.wk5-nav a:focus-visible,
.wk5-nav summary:focus-visible {
  outline: 3px solid #2457d6;
  outline-offset: 3px;
}

/* Adding this second class changes the same menu into a vertical list. */
.wk5-nav.wk5-nav-overlay {
  flex-direction: column;
  align-items: stretch;
}

/* Stack the top navigation on small screens too. */
@media (max-width: 600px) {
  .wk5-nav { flex-direction: column; align-items: stretch; }
}

B. Put the dropdown inside a Cargo overlay

Reuse the overlay menu from Week 3. Paste the same navigation HTML into the overlay page’s Code View, then replace its opening nav line with the line below. Keep the rest of the HTML and the closing nav tag. The additional class stacks the menu vertically; the CSS above already includes its rules.

<nav class="wk5-nav wk5-nav-overlay" aria-label="Overlay navigation">
  1. In Cargo’s Pages menu, right-click the menu page and set it to Overlay. Choose its position and width with Cargo’s visual controls.
  2. On your top navigation page, create a Menu text link or icon. Select it, open Link → Link to Page, and choose the overlay page. Cargo creates the overlay behaviour; the dropdown code does not open the overlay itself.
  3. Inside the overlay, add a Close text link or icon and assign Link → Navigate → Close Overlay. Enable Close on clickout and Close on navigate where appropriate.
  4. Preview the site. Open Menu, expand Work, follow a project link, reopen the menu and test Close. Check Escape closes the Cargo overlay. The nested Work disclosure closes by activating Work again; it does not have a separate Escape or click-outside handler.

Check: Test on desktop and mobile, then use Tab, Shift+Tab and Enter without a mouse. Every destination should work, every focused item should be visible, and long labels should remain readable. Give your overlay enough space to show the expanded submenu.

Copy and paste: hover states for a Cargo button

Start with an existing Cargo button and keep its design. Add CSS to change its appearance on hover, keyboard focus and press. No new HTML is needed for this exercise.

A. Choose and link your Cargo button

  1. Select an existing button on your page. If you need one, use Add... → More... → Button... and choose a Cargo preset.
  2. Edit the label, then use Link → Link to Page to assign its destination. A button style alone does not create a working link.
  3. Use Cargo’s visual controls to set its normal colours, spacing and shape. Choose a filled button for this example so the brightness change is easy to see.

B. Find the button’s existing CSS selector

With the button text selected, identify its Text Style. Open that style in Text Styles (Aa) and click its </> control. Find the selector before the opening brace of the rule that styles this button. Copy the selector exactly, including its leading dot if it is a class. Cargo’s generated style names vary, so do not assume every button uses the same class.

In the snippet below, replace every occurrence of .button-example with that actual selector. For example, if the style rule begins .button-1 {, use .button-1:hover. The name .button-1 is illustrative: use the name shown in your own editor. If unsure, Inspect the button in the browser and identify the element that carries its background, border and padding.

C. CSS — paste at the end of Site Settings → CSS/HTML → CSS

Keep the existing style rules. Paste this additional CSS below them, without <style> tags. It affects all buttons sharing the selected style; duplicate the Text Style in Cargo first if you want a separate style for one button.

/* Replace .button-example everywhere with your Cargo button style selector.
   Copy that selector from the button Text Style's CSS panel.
   This is an example name, not a universal Cargo button class. */
.button-example {
  /* Keep the original Cargo colours, border, padding and shape. */
  transition: filter 180ms ease;
}

/* Slightly darken the existing button when hovered or focused.
   focus-within also works when Cargo places a link inside the style. */
.button-example:hover,
.button-example:focus-visible,
.button-example:focus-within {
  filter: brightness(0.85);
}

/* Make keyboard focus easy to see. */
.button-example:focus-visible,
.button-example:focus-within {
  outline: 3px solid #2457d6;
  outline-offset: 4px;
}

/* A stronger response while the button is being pressed. */
.button-example:active {
  filter: brightness(0.7);
}

/* Remove animation for visitors who prefer reduced motion. */
@media (prefers-reduced-motion: reduce) {
  .button-example { transition: none; }
}

What changes? :hover responds to the pointer. :focus-visible marks keyboard focus on the styled element; :focus-within also handles a focused link inside it. :active lasts while pressed, not after a click. Brightness changes the rendered button, including its text, without replacing Cargo’s base design.

Test and adapt: Preview outside edit mode. Hover, then use Tab and Enter to focus and follow the link. Test on mobile, where hover may not appear. Try brightness values of 0.95 and 0.85 and choose the clearer result. Keep text readable in every state and make sure the normal button is recognisable without hover. If nothing changes, check the copied selector and use Inspect to see whether another rule overrides it. If an existing style already uses a filter or transition, merge these changes with that rule rather than overwriting its effect.

D. Variation: shift the hue on hover

Choose an existing Cargo button with a coloured fill using Cargo’s visual controls. This variation rotates its colours on hover and keyboard focus, then uses a second hue while pressed. Black, white and neutral grey will not show a noticeable hue shift.

Where to paste: In the site CSS editor, replace the brightness example from section C with this snippet. Replace every .button-example with your button’s actual style selector. Use one variation at a time so competing filter rules do not override each other.

/* Replace .button-example with your existing Cargo button selector.
   Use this INSTEAD of the brightness example above. */
.button-example {
  transition: filter 180ms ease;
}

/* Shift the existing colours around the colour wheel on hover/focus. */
.button-example:hover,
.button-example:focus-visible,
.button-example:focus-within {
  filter: hue-rotate(60deg);
}

/* Keep keyboard focus visible. */
.button-example:focus-visible,
.button-example:focus-within {
  outline: 3px solid #2457d6;
  outline-offset: 4px;
}

/* A different hue while the button is pressed. */
.button-example:active {
  filter: hue-rotate(120deg);
}

/* Respect reduced-motion preferences. */
@media (prefers-reduced-motion: reduce) {
  .button-example { transition: none; }
}

Experiment: Compare hue-rotate(30deg), hue-rotate(90deg) and hue-rotate(180deg) in the hover rule. A full 360deg returns to the original hue. Choose one that supports your palette and document the alternatives in your journal.

The filter affects the whole rendered button, including coloured text, borders, icons and its focus outline; it does not change only the background. Check text contrast and keyboard focus in every state. For an exact brand colour on the background alone, use a background-colour rule instead. Test on mobile too: the normal button must remain clear without hover.
